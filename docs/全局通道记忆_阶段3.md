## 记录与失效

记忆只接受明确的地图会话 `epoch`、`map` 坐标系、地图几何，以及带独立 `evidence_id` 的新鲜、至少三帧确认结果。测试使用合成确认结果；实际 ROGMap 目前尚未给大洞口产生净空通过结果。

- 传感器离开局部观测范围，不自动忘记历史结构。修正层仍需要持续收到由记忆生成的证据快照；证据不再发送时其原有超时机制恢复静态墙。
- 新障碍冲突、地图会话或地图几何变化、`map→odom` 相对记忆创建时位移超过 0.25 m 或转角超过 0.15 rad，记录进入 `SUSPENDED`。
- 暂停后的记录不会因为位姿再变回来而复活。相同的 `evidence_id` 不能再次使用，必须取得新验证。

已加入原子文件保存/恢复和完整性校验；相同地图会话、地图几何与 `map→odom` 关系经调用方重新确认时，可在进程重启后恢复**历史结构候选**。地图标识不符、坐标修正过大或文件损坏时拒绝恢复。文件哈希只防意外损坏，不是防伪认证。真实系统仍须从 SLAM/位姿图提供可核验的地图会话标识、地图关联以及回环后关键帧重定位；目前没有把该文件记录接到实车清障或入口许可。

实测 ROGMap 现可在 `clearance.enabled=true` 且 `clearance.publish_verified_segments=true` 时，向 `/terrain/clearance/verified_segment` 发布**短段观测**。输出仅在全部体素、地面支撑、时间门限及三次新增直接观测确认通过后出现；同一张图重复读取不增加确认数。仿真入口外多视角扫描在 0.2 m 行进段上获得 432 个体素的通过证据，但不代表整个隧道可通行。

新增 [live_memory_shadow.py](/home/zst/zzs_rogMAP/src/rm_perception/sentry_passage_fusion_test/scripts/live_memory_shadow.py)：只读订阅上述证据、`/map` 和 TF，在证据时刻查询 `map←odom`，保存候选所在地图区域；重启后核对声明的地图会话、地图几何、TF 变化及候选区域的静态地图内容。发布 `/passage/memory_shadow_status`，其中 `entry_allowed=false`、`costmap_override=false` 恒为假。它**不发布 Nav2 掩码，不自动生成探针，不接控制器**。显式 `map_session_id` 仅由操作者声明，尚不能证明两个 SLAM 位姿图完全相同；跨重启恢复只能称为“通过当前检查的影子候选”，不能直接用于实车清障。

运行前必须显式给出非空 `map_session_id` 和绝对 `record_path`；没有 `/map` 或 `map←odom` TF 时只报告等待，不建立候选。候选地图局部像素一变即暂停，可能较保守，但不会把变化后的地图继续当旧通道。实车 `rog_map_real.yaml` 仍未启用 clearance 输出，实车启动配置也没有加入此节点。

本轮 ROS 接线测试在独立域 220 用前述真实 ROGMap 输出的字段/尺度重新赋测试时钟，检查了话题接收、TF 变换、文件写盘、节点重启恢复和地图局部修改后的撤销；它没有连接 NUC 的实时 SLAM，也不是隧道通行验收。

## 检验

```bash
source /opt/ros/humble/setup.bash
source ~/zzs_rogMAP/.passage_lab/install/setup.bash
ctest --test-dir ~/zzs_rogMAP/.passage_lab/build/sentry_passage_fusion_test --output-on-failure
```

`passage_memory` 检查多帧门槛、重放拒绝、障碍冲突、地图重载和坐标修正后的暂停。
`fusion_integration` 还读取真实测试宿主发布的 Master Costmap，检查不再提供新的局部验证、但记忆持续发送测试证据超过一秒后仍保留可跨墙通路，随后冲突恢复静态墙；原有第一阶段开洞、撤销、超时、障碍否决回归也继续运行。此测试没有移动真实传感器或接入第二阶段 ROGMap 节点。

本轮验证：3/3 CTest 通过，`fusion_integration` 共 50 个检查点通过；原始 `/map` 未被修改，没有运动控制发布。

下一阶段入口管理须在规划路径触及受控区域前设安全观察点，确认制动距离和重新验证状态，并防止导航恢复行为绕过许可。当前测试没有任何运动控制；“有历史通道”绝不等于“获准驶入”。
