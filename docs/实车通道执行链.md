# 实车通道执行链：先看 Costmap 是否真正开洞

更新：2026-10-18。运行设备为 doublegun 的 NUC，工作空间为 `~/zzs_rogMAP`。

## 这次验证什么

把车停在真实洞口前，让雷达采集真实数据，观察：**SLAM 原始地图中被画成墙的洞口，是否因为 ROGMap 的真实通行证据，在最终全局 Costmap 中变成缺口。**

本轮不要求自动穿洞，不要求先完成跨重启记忆测试，也不要求扫描完整条隧道。先证明真实感知结果确实进入导航地图。当前还没有 NUC 上稳定开洞的完整验收证据，不能把本地测试通过当作实测成功。

| 显示对象 | 含义 | 本次用途 |
| --- | --- | --- |
| `/map` | SLAM 的原始二维地图 | 对照：洞口原来是否被当成墙 |
| `/terrain/grid` | ROGMap 输出的局部二维地形 | 排查：地形投影如何分类；不是最终导航结果 |
| `/global_costmap/costmap` | Nav2 多层融合、膨胀后的全局代价地图 | 验收：静态假墙是否真正被修正 |

**修正层不改写 `/map`。“原图仍然有墙、最终 Costmap 出现缺口”正是要观察的效果。**

## 1. 启动：只观察，不驱动车

前提是最新源码已经同步到 NUC 并成功编译。重新编译旧源码不等于更新。首次部署或缺依赖时查 [技术参考](实车通道执行链_技术参考.md)，不必每次观察都清理、编译。

关闭旧的导航启动进程，不要同时运行另一套 Nav2、串口控制或旧 bringup。在 NUC 新终端执行：

```bash
cd ~/zzs_rogMAP
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch sentry_passage_fusion_test passage_real.launch.py \
  mode:=mapping lio:=fastlio enable_motion:=false rviz:=true
```

如果原来使用 Point-LIO，只把 `lio:=fastlio` 换成 `lio:=pointlio`，不要为这次观察更换已经可用的里程计。

此入口仍计算感知、建图、规划和门控，但不启动串口，底盘输出桥只输出零速。它不能替你关闭其他独立运行的控制程序。

等机器人、实时扫描和地图出现。若地图或 TF 报错，保留报错，不要把空白画面当成清障成功。

## 2. 看原图：确认要修正哪一堵“假墙”

在 RViz 左侧操作，不需要终端命令：

1. `Global Options → Fixed Frame` 保持 `map`。
2. 勾选 `Map`，展开确认话题为 `/map`。
3. 暂时取消 `Global Planner → Global Costmap`、`Controller → Local Costmap`、`ROGMap Terrain` 和二维分类显示。三维点云也可先关掉，避免遮挡。
4. 调整视角，让真实洞口、机器人及附近墙体清楚可见，记住洞口位置，最好截图。

需要的是“实际有洞，但原图把这一段画成障碍”。如果原图本来就是通路，不能用它证明静态清障生效；未知区域也不是已确认的静态墙。

## 3. 指定观察方向：用 Publish Point

把车放在入口外、能观察洞口的位置。点击顶部 **Publish Point**，在地图上点击洞口另一侧的地面位置，使“机器人到点击点”的连线穿过真实洞口。

不要点到旁边实墙或机器人脚下。当前协调器沿这个方向寻找静态地图冲突，再请求三维净空验证。这个操作只指定探测方向，**不发送行驶目标，也不会让车自动靠近。**

等待真实扫描更新。条件允许时可从入口外调整观察位置，比较正面和左右视角；须由你安全地人工安排，本流程不自动控制扫描运动。

当前验证按短段推进。车不前进时，不应期待整条深隧道一次全部打开。未观测空间不自动算作自由空间，但也不把“提前扫描整条隧道”作为本轮要求。

## 4. 切到最终地图：最关键的对照

保持相同视角：

1. **取消勾选 `Map`**，隐藏原始地图。
2. 勾选 `Global Planner` 组内的 **`Global Costmap`**，确认话题为 `/global_costmap/costmap`。
3. 展开此项，`Color Scheme` 设为 `costmap`，`Alpha` 设为 `1.0`。其他地形图、局部地图和 `Downsampled Costmap` 暂时关闭。
4. 看同一个洞口：原先连续的障碍带是否断开，出现连接入口两侧的低代价缺口。

在 `Map` 和 `Global Costmap` 之间分别切换。不要同时叠加判断：Costmap 自由区域可能透明，底下原图的黑墙会透出来，造成“开洞仍是黑的”的假象。

没有逐格数字是正常的，代价主要用颜色表示。颜色受显示方案影响，不能只凭“黑/紫”判断。**一两个格子变色只说明局部变化，不代表形成了整车可规划的通道。** 膨胀后的剩余宽度也要足够。

## 5. 有缺口之后，看规划是否利用它

保持 `enable_motion:=false`，启用 `Global Planner → Path`，用 **Nav2 Goal** 在洞口另一侧可通行地面设置目标。

看新路径是否实际穿过缺口，而非绕路、终止在墙前或仍显示旧路径。Publish Point 和 Nav2 Goal 目前是两个操作：前者探测，后者规划。

本轮成功应有同一处洞口的三个对照：

- 原始 `/map`：仍是静态障碍。
- 最终全局 Costmap：对应位置形成缺口。
- 新的全局路径：确实穿过该缺口。

这证明“真实感知 → 地图修正 → 规划利用”，**不等于获得入口许可或完成实车自动穿洞**。本轮不启用底盘运动。

## 没看到开洞，怎么办

原图不变本来就是预期，需要排查的是最终图为何没变。不要为出效果关闭 TerrainLayer、改低真实车高或把未知当自由。

| 现象 | 下一步关注什么 |
| --- | --- |
| 只有 `/terrain/grid` 变化 | 还没证明证据、记忆和修正层已接通 |
| 没有真实净空证据 | 探测位置、观测覆盖及具体拒绝原因；不要先改 Nav2 |
| 有修正证据，最终图仍封闭 | TerrainLayer 是否重新标障、膨胀是否堵住缺口、证据是否对齐 |
| 最终图有缺口，但规划失败或绕路 | 剩余宽度、起终点、连通性和新路径；单格清除不够 |
| 原图和最终图空白或报错 | 数据或显示问题，不是开洞结果 |

不清楚卡在哪一步时，只运行下面的只读检查，保留完整输出：

```bash
ros2 run sentry_terrain_bridge real_passage_diagnostics \
  --lio fastlio --seconds 15 --fusion --expect-opening
```

新终端先加载 ROS 和本工作空间；Point-LIO 用 `--lio pointlio`。此命令不发目标、不控制车。它统计证据覆盖的原始墙格在最终地图中的变化，不能代替通道宽度与路径验收。

**未开洞可能是合理拒绝，但仍表示本轮实车开洞效果未通过，不能以“安全逻辑正确”代替交付结果。** 当前默认仍为老车真实尺寸 0.45 × 0.45 × 0.70 m；测试洞口若低于该高度，不应期待获得整车通行证据。换车后填写实测值，这与是否接通融合链是两个问题。
