# 实车通道执行链：技术参考

日常实测先读 [实车通道执行链](实车通道执行链.md)。本页保留部署、录包、诊断、地图交接与实现细节，按需要查阅，不要求首次看效果时逐项执行。

## 当前入口

```bash
cd ~/zzs_rogMAP
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-up-to sentry_passage_fusion_test rm_navigation rm_nav_bringup
source install/setup.bash
```

默认启动传感器、LIO、ROGMap、SLAM、Nav2、记忆、探针协调器、入口门控和输出桥。

禁止被包含的 bringup 再启动第二套 Nav2。

### NUC 上按顺序验收

先保持 `enable_motion:=false`，确认 `/scan`、`/map`、`map→base_link`、
`/terrain/clearance/verified_segment`（有真实净空证据时）、
`/passage/memory_status` 和 Nav2 全局代价地图都正常。没有洞口证据时，
`verified_segment` 不发布是正确的，不要用人工消息代替。

```bash
ros2 topic hz /scan
ros2 run tf2_ros tf2_echo map base_link
ros2 topic echo /passage/memory_status --once
ros2 topic echo /passage/probe_status --once
ros2 topic echo /passage/entry_gate_status --once
ros2 topic info /passage/chassis_cmd_vel -v
```

P3（NUC 实机、禁止运动）先核对实际加载的全局图层，再在 RViz 对照同一个洞口：

```bash
ros2 param get /global_costmap/global_costmap plugins
ros2 param get /global_costmap/global_costmap static_layer.map_topic
ros2 param get /global_costmap/global_costmap static_correction_layer.evidence_topic
ros2 topic info /terrain/clearance/verified_segment -v
ros2 topic info /passage/verified_static_clearing -v
ros2 topic info /global_costmap/costmap -v
ros2 run sentry_terrain_bridge real_passage_diagnostics --lio fastlio --seconds 8 --fusion
```

诊断同时监听 `/plan` 和 `/passage/entry_gate_status`；前者若未在观察窗口内
发布，会显示 `OPTIONAL_ABSENT`，不能把“没看到路径”当成规划成功。
保持 `enable_motion:=false`，在终端启动 15 秒的只读检查后，用 RViz 向
洞口另一侧发送 Nav2 Goal；若要让命令在无路径、路径未穿过证据墙格或最终
地图未开洞时以非零状态退出，使用：

```bash
ros2 run sentry_terrain_bridge real_passage_diagnostics --lio fastlio --seconds 15 --fusion --expect-path
```

应在诊断结束前观察到新鲜的 `FUSION_PATH ... crosses_claimed_static_wall=True`，
并保留同一轮的 `FUSION_STATIC_WALL_CELLS`、`FUSION_TERRAIN_AT_CLAIMED_WALL`
和门控状态。此命令自己不发送 Goal、速度或许可。规划路径穿洞不等于准许进入；
门控在缺少近期净空验证时仍应保持 `WAIT_VERIFY` 或 `BLOCKED`。

预期图层顺序为 `static_layer, static_correction_layer, terrain_layer, inflation_layer`，
地图话题为 `/map`，修正证据为 `/passage/verified_static_clearing`。在默认 `nav2.rviz`
中分别打开左侧 `Map`（原始 `/map`）与 `Global Planner → Global Costmap`
（最终 `/global_costmap/costmap`）；对照时一次只显示其中一层，避免半透明叠加遮住洞口。
真实证据出现后，原始 `/map` 可以仍是墙，但最终 Costmap 必须在对应位置出现
可规划缺口，且 `/plan` 必须实际穿过；否则 P3/P6 未通过。没有真实净空证据时，
`verified_segment` 不发布、静态墙不被清除是正确的安全行为。
在真实洞口证据出现且掩码持续发布时，可改用同一只读命令加
`--expect-opening`：它会统计 `/map` 中被证据标记的静态墙格在最终
Costmap 里有多少已变为非致命代价。`final_blocked_or_inscribed` 不为零时，
还要检查后续 TerrainLayer 或 InflationLayer 是否重新封住该区域；
诊断输出的 `final_nonlethal` 仅表示单格代价不是致命值，并不证明整车
净空、可规划路径或入口许可；此统计不替代 RViz 逐格核对、`/plan`
路径和入口门控验收。新增 `FUSION_TERRAIN_AT_CLAIMED_WALL` 会在同一批
证据格上比较当前 `/terrain/grid`：若 `occupied` 非零，同时最终 Costmap
仍封闭，优先核对三维车体净空证据和二维地形投影是否冲突；不能直接关闭
TerrainLayer，因为它仍承担实时障碍否决。该比较使用收到的单帧地形栅格和
对应时间的 TF，只是定位封洞原因，不是给车辆通行授权。

在 RViz 用 Publish Point 指向疑似通道，观察探针和净空证据；地图修正层
只接受真实验证段。确认全局地图打开后，再用 Nav2 Goal 检查规划。
这两个操作目前是分开的，不会自动把探针点发为行驶目标。

切换已保存地图定位时，使用 `mode:=nav world:=地图名 localization:=slam_toolbox`
（或只具备图像地图时 `localization:=amcl`），仍先关闭运动检查地图、定位、
全局路径和入口门控。没有通过这些检查，不要加 `enable_motion:=true`。

建图结束后，在建图节点仍运行时保存同名前缀的地图文件：

```bash
./save_passage_map.sh new_map
```

从2026-10-23起，`mapping.sh`与`nav.sh`统一Point-LIO；建图使用水平
`lidar_scan`，停车保存新名字。脚本要求Point-LIO快照服务与SLAM序列化服务，
保存`.posegraph`、`.data`、`.yaml`、`.pgm`、同名map系PCD及
`.registration.json`。PCD复用Point-LIO累积点云，按选定地图时间戳的完整
map←odom变换导出；二维图保存同一份选定快照。文件哈希与变换随新图保存，
拒绝覆盖，源码和安装目录自动同步，无需手工复制旧PCD。

旧test1保留，不把FAST-LIO旧图直接当作当前水平扫描的新图验收。保存成功后
停止建图进程，再按需要显式导出这一
建图会话的历史通道记录；不要直接改 JSON 里的会话 ID：

```bash
ros2 run sentry_passage_fusion_test passage_record_handover.py \
  --world new_map --localization slam_toolbox \
  --source "$HOME/.ros/passage_memory/runtime.json" \
  --output "$HOME/.ros/passage_memory/new_map.json"
ros2 launch sentry_passage_fusion_test passage_real.launch.py \
  mode:=nav world:=new_map localization:=slam_toolbox \
  record_path:="$HOME/.ros/passage_memory/new_map.json" enable_motion:=false
```

导出只复制历史结构候选，原建图记录保留；不导出入口许可。导航启动后
若地图几何或静态墙格不匹配，记录会被撤销或挂起。保存地图导航重启后，
`odom` 原点可改变，历史结构将以当前 `map→odom` 建立新基准；之后运行中
TF 若发生超限突变仍会挂起。任何情况下入口许可都必须重新观测取得，
不能靠重复导出强行放行。切换到 AMCL/ICP 时相应修改
`--localization`，并准备它们需要的地图文件。
若需要底盘运动，先在架空/安全区域核验唯一串口进程、零速停车、遥控优先权和
MCU 断指令停车，再显式启用运动；此项不能从本机测试代替。
先用 `ls -l /dev/serial/by-id/` 找稳定设备名，并用
`sudo fuser -v /dev/ttyUSB0` 检查是否有旧 `trans_node2` 或其他程序占用；
不要和旧启动入口同时打开同一个串口。将核实后的设备传给 `serial_port:=...`。

已有传感器/SLAM 时可用 `start_sensors:=false`，但需要原地形节点启用
`clearance.publish_verified_segments`，不能使用虚拟预览证据。

## 实际数据链

1. ROGMap 净空验证 → `/terrain/clearance/verified_segment`。
2. 运行记忆节点 → `/passage/memory_status`、`/passage/verified_static_clearing`、`/passage/fresh_permit`。
3. 全局图层顺序：StaticLayer → StaticCorrectionLayer → TerrainLayer → InflationLayer。
4. Nav2 速度平滑器及恢复动作 → `/passage/nav_cmd_vel`（不再直接进入底盘）。
5. 运行桥读取 `/plan`、`/Odometry`、`map→base_link`、`/local_costmap/costmap`。
6. 入口门控 → `/passage/cmd_vel_authorized`。
7. 运行桥 → `/passage/chassis_cmd_vel`。显式启用运动时，launch 才将 trans_node2 的输入重映射到这里。

测试证据话题、虚拟 0.32 m 车体证据均不被运行记忆节点接受。
历史记忆可用于规划；当前有效许可才允许进入受控段。

## 参数与文件

- `mode:=mapping`：在线建图。`mode:=nav world:=地图名 localization:=slam_toolbox`：已有地图定位，要求同名前缀 `.posegraph`、`.data`、`.yaml` 和图像都存在。
  只有图像和 `.yaml` 时选择 `localization:=amcl`；`localization:=icp` 还需要
  `PCD/地图名.pcd`。启动前会检查并纳入地图标识，缺文件直接报错。
- `lio:=fastlio` 或 `pointlio`，不修改原实车外参。
- `robot_height:=0.70 robot_length:=0.45 robot_width:=0.45`：默认老车尺寸，
  同时传给三维净空验证和运行时局部扫掠。换车后应一并填写实测值；不是演示车尺寸。
- `ground_z_offset:=-0.23`：按用户提供老车 base_link 离地 0.23 m，用于探针落地坐标；没有改 URDF 或地面分割参数。
- `map_session_id`：建图模式每次自动新建唯一会话，不接受手填；已有地图导航模式根据实际地图文件内容计算稳定标识，且不能手填其他值绕过校验。地图文件任一部分变化后旧记忆不能自动复用。TF 关联仍需单独验证，历史记录绝不恢复通行许可。
- `record_path`：默认 `~/.ros/passage_memory/runtime.json`。原子保存、校验恢复；恢复的是结构，不恢复通行许可。
- `serial_port`：默认 `/dev/ttyUSB0`，部署时应选择已确认的设备路径。

## 已验证与未完成

已完成本地编译：地形桥、融合包、导航配置、bringup、decision/trans_node2 及其接口依赖。
真实 trans_node2 二进制通过伪串口协议帧验证：启动零速、无接收数据时仍持续发送、
250 ms 指令超时后零速、nav_ready=0 禁止运动、NaN 输入拒绝。未连接真实串口。
独立 ROS 域测试已验证运行记忆→门控→底盘话题连接，正常自由路径输出、局部图过期停止、目标取消停止、导航速度断流停止。
没有连接串口或驱动车辆，此结果不是实车穿洞验收。
统一入口已执行无传感器、无串口启动检查，修复了新入口脚本缺少执行权限的问题。
该检查未提供地图/TF，且本机沙箱限制 DDS 网络，不能据此认为 Nav2 已激活完成。

仍需完成：

1. 首次发现静态假墙时，Nav2 可能无路径，因此 `/plan` 不会产生目标。
   当前协调器可以接收 `/passage/desired_goal` 或经桥转发的 `/goal_pose` 作为只读探测目标，
   但**不会自动将此目标发成 Nav2 动作**。需要把 RViz 导航目标与探针目标可靠关联，避免两次设置目标。
2. 局部检查目前将 unknown 和代价 99/100 均视为阻塞，外加包围圆扫掠，可能过于保守；
   未授权放宽。遇到 WAIT_VERIFY/BLOCKED 应查看原因，而不是改成强行放行。
3. 本机已在临时目录补齐 `serial` 库并完成上述测试；NUC 仍需使用其真实串口核验设备、协议和遥控优先权。
4. 主机退出/断电时须由底盘 MCU 的指令超时独立停车。遥控优先权仍需实机核验。
5. 建图→已保存地图的记录交接已提供显式导出命令，但还没有在 NUC 的真实建图文件、定位 TF 和通道记录上验收。导航模式在同一份保存地图上重启可恢复结构候选；两种场景都需 TF/地图格验证并重新取得入口许可。
6. 新底盘外参确认后才能替换物理尺寸。老车机械无法通过的洞口，不会被配置成可通过。
7. 源码核对发现 `TerrainLayer` 位于修正层之后；若 ROGMap 当前二维地形仍将洞口
   标为占据，最终 Costmap 会再次封洞。NUC 上先用 `--fusion --expect-opening`
   对照真实证据与最终代价，确认这个现象是否发生；不能为了让图上开洞而直接
   关闭实时障碍层。

## 串口修改

trans_node2 新增 `serial_port` 和 `command_timeout`（默认 0.25 秒）。
没有新命令时周期发送零速；断线后丢弃缓存速度；读取不再持锁等待首字节；
正常退出尽力发送零速。这不替代 MCU 超时保护。

### NUC 串口依赖

本地验证所用 ROS2 serial 源码版本记录在工作空间根目录 `serial_dependency.repos`。
先检查 NUC 是否已有 `serial` 包；有则不要重复导入。没有时可在工作空间执行：

```bash
vcs import src < serial_dependency.repos
colcon build --symlink-install --packages-up-to decision
```

## 验收观察点

观察 `/passage/memory_status`、`/passage/entry_gate_status`、`/passage/probe_status`。
依次核对原 `/map`、三维占据、证据区域、全局代价地图、门控输出。
首次遇到 SLAM 假墙且 Nav2 还没有路径时，在 RViz 用 **Publish Point** 点击洞口方向；
该点只触发 `/passage/desired_goal` 候选探测，不向 Nav2 发送行驶目标。
确认全局代价地图中通道已被经过验证的证据打开后，再用 Nav2 Goal 设置导航目标。
先在禁止运动状态用真实扫描验证这些接口，再核验唯一串口进程与停止行为。
本版本未完成所有部署条件，不能直接称为已完成实车自动过洞。
